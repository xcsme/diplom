Такие приложения развивают аналитическое мышление, навыки финансового планирования и стратегического управления ресурсами. # Глава 1. Анализ и постановка задачи

## 1.1 Описание предметной области

Предметной областью настоящего дипломного проекта является индустрия компьютерных игр, а именно жанр экономических симуляторов (менеджеров). Экономические симуляторы — это класс игровых приложений, в которых пользователь берёт на себя роль управляющего каким-либо бизнесом или организацией и принимает решения, влияющие на финансовые показатели, развитие и успешность управляемого объекта.

В частности, рассматривается симуляция управления небольшой кофейней. Кофейная индустрия представляет собой динамичный сегмент общественного питания. По данным Международной организации кофе (ICO), мировое потребление кофе ежегодно растёт на 2–3%. В России количество кофеен также неуклонно увеличивается, что свидетельствует о высоком интересе к данной сфере.

Основные процессы, которые характеризуют деятельность кофейни и подлежат моделированию:
- **Закупка ингредиентов.** Владелец кофейни регулярно приобретает сырьё: кофейные зёрна, молоко, сахар, сиропы, выпечку и расходные материалы (стаканы). Цены на ингредиенты могут колебаться в зависимости от рыночных условий.
- **Формирование меню и ценообразование.** Определение ассортимента напитков и продуктов, установка цен продажи с учётом себестоимости и ожидаемого спроса.
- **Обслуживание посетителей.** Поток клиентов зависит от репутации заведения, качества обслуживания и внешних факторов. Каждый клиент делает заказ, и его удовлетворённость влияет на репутацию.
- **Управление персоналом.** Найм и обучение барист, привлечение менеджера для автоматизации отдельных процессов.
- **Развитие и модернизация.** Приобретение нового оборудования (кофемашины, холодильники, витрины), проведение маркетинговых кампаний.
- **Учёт и анализ.** Ведение статистики продаж, выручки, расходов, отслеживание изменения репутации.

Участники процесса включают владельца кофейни (роль игрока), персонал (бариста, менеджер), посетителей (генерируются системой) и поставщиков ингредиентов.

До автоматизации (то есть в отсутствие разрабатываемого приложения) процесс изучения основ управления кофейней возможен только через теоретические материалы, курсы или непосредственно через реальный бизнес-опыт. Существующие образовательные ресурсы часто ограничиваются текстовой информацией и не обеспечивают интерактивного взаимодействия. Реальный бизнес сопряжён с финансовыми рисками и недоступен для большинства потенциальных предпринимателей на этапе изучения.

Основные проблемы, требующие решения:
1. Отсутствие интерактивного инструмента, позволяющего моделировать управление кофейней в безопасной среде.
2. Недостаток специализированных игровых продуктов на русском языке, ориентированных именно на кофейную индустрию.
3. Необходимость обеспечения сохранения прогресса и ведения статистики для анализа принятых решений.
4. Потребность в кроссплатформенном решении, не требующем установки.

На основании проведённого анализа обоснована необходимость разработки веб-приложения экономического симулятора кофейни, которое обеспечит:
- интерактивное моделирование бизнес-процессов кофейни;
- пошаговый игровой процесс с элементами случайных событий;
- систему учёта и визуализации статистики;
- сохранение прогресса между игровыми сессиями;
- доступность через веб-браузер.

## 1.2 Анализ существующих решений и аналогов

Перед началом разработки проведён анализ существующих программных продуктов, относящихся к жанру экономических симуляторов с тематикой общественного питания. Критериями сравнения выбраны: функциональные возможности, наличие русскоязычного интерфейса, платформа, стоимость, наличие системы статистики и сохранения, а также образовательный потенциал.

**1. Coffee Inc 2 (SideRoad Studio)**

Назначение: мобильная игра-симулятор кофейного бизнеса.

Основные функции: управление несколькими кофейнями, найм персонала, выбор рецептов, управление финансами, маркетинговые кампании.

Платформа: iOS, Android.

Преимущества: детальная проработка экономической модели, большое количество контента, хорошая графика.

Недостатки: отсутствие веб-версии, интерфейс на английском языке, монетизация через внутриигровые покупки, закрытый исходный код.

**2. Idle Coffee Corp (Noodle Games)**

Назначение: idle-симулятор кофейного бизнеса.

Основные функции: автоматизированное управление, развитие сети кофеен, минимальное взаимодействие игрока.

Платформа: Android, iOS.

Преимущества: простота освоения, не требует постоянного внимания.

Недостатки: примитивная экономическая модель, отсутствие стратегической глубины, нет веб-версии, нет русского языка, нет статистики.

**3. Game Dev Tycoon (Greenheart Games)**

Назначение: экономический симулятор разработки игр (аналогия по жанру).

Основные функции: управление ресурсами, принятие решений, развитие компании, случайные события.

Платформа: Windows, macOS, Linux, iOS, Android.

Преимущества: глубокая экономическая модель, детальная статистика, система достижений.

Недостатки: иная тематика (не кофейня), отсутствие веб-версии, платный продукт.

**4. My Cafe (Melsoft Games)**

Назначение: социальная игра-симулятор кафе.

Основные функции: управление кафе, обслуживание клиентов, выполнение заказов, декорирование.

Платформа: iOS, Android.

Преимущества: русский язык, красочная графика, социальные функции.

Недостатки: акцент на декорировании, а не на экономике; агрессивная монетизация; нет веб-версии; ограниченная статистика.

## 1.3 Постановка задачи и функциональные требования

**Цель разработки.** Разработать веб-приложение экономического симулятора «Кофейня: Мастерская вкуса» с клиент-серверной архитектурой, обеспечивающее пошаговый игровой процесс управления кофейней, ведение статистики, систему достижений и сохранение прогресса.

**Постановка задачи.** Требуется разработать интерактивное веб-приложение, моделирующее деятельность кофейни. Приложение должно предоставлять пользователю интерфейс для принятия управленческих решений (закупка ингредиентов, формирование меню, установка цен, улучшения оборудования и персонала) и автоматически симулировать рабочий день кофейни с генерацией потока посетителей, обработкой заказов и расчётом финансовых показателей.

**Функциональные требования:**

Система должна обеспечивать:
1. Создание новой игровой сессии с указанием имени игрока.
2. Загрузку ранее сохранённой игровой сессии.
3. Отображение текущего состояния ресурсов (деньги, репутация, текущий день).
4. Управление складом ингредиентов: просмотр остатков, закупка с указанием количества.
5. Управление меню: установка цен на позиции, включение/выключение позиций.
6. Систему улучшений: приобретение оборудования, найм персонала, маркетинговые кампании.
7. Симуляцию рабочего дня: генерацию посетителей, обработку заказов, расчёт выручки и расходов.
8. Генерацию случайных событий (16 типов) с вероятностью 20–30% в день.
9. Формирование отчёта по итогам дня с детализацией.
10. Систему достижений (15 достижений) с автоматическим отслеживанием и уведомлениями.
11. Визуализацию статистики в виде графиков (выручка, репутация, удовлетворённость).
12. Лог событий с фильтрацией по дням.
13. Условие победы (накопление 100 000 рублей) и условия поражения (банкротство или нулевая репутация).
14. Автосохранение прогресса после каждого завершённого дня.
15. Звуковое сопровождение действий и фоновый эмбиент.
16. Управление звуком (включение/выключение).
17. Возврат в главное меню из игровой сессии.

**Нефункциональные требования:**
- Производительность: время отклика серверной части не более 500 мс.
- Надёжность: сохранение данных в БД с обеспечением целостности.
- Удобство: интуитивно понятный интерфейс с подсказками.
- Совместимость: работа в современных браузерах (Chrome, Firefox, Safari, Edge).
- Фиксированное разрешение игрового окна: 1024×768 пикселей.
- Интерфейс полностью на русском языке.

## 1.4 Выбор технологий и инструментов

Разрабатываемое приложение представляет собой клиент-серверное веб-приложение. Требования к системе предполагают: интерактивный пользовательский интерфейс, серверную бизнес-логику, хранение данных в базе данных и взаимодействие через HTTP API.

**Язык программирования серверной части: Python 3.10+**

Python выбран в качестве основного языка серверной разработки по следующим причинам: высокая скорость разработки, обширная экосистема библиотек, удобный синтаксис, широкая поддержка со стороны сообщества. Python является одним из наиболее распространённых языков для разработки веб-приложений и прототипирования.

Альтернативы: Node.js (JavaScript), Go, Java. Node.js мог бы быть использован для унификации языка на клиенте и сервере, однако Python обеспечивает более удобную работу с математическими расчётами игровой логики.

**Фреймворк серверной части: FastAPI**

FastAPI — современный высокопроизводительный фреймворк для создания REST API на Python. Ключевые преимущества: автоматическая генерация документации (Swagger/OpenAPI), встроенная валидация данных через Pydantic, поддержка асинхронных операций, высокая производительность.

Альтернативы: Django, Flask. Django был бы избыточен для данного проекта, так как содержит множество неиспользуемых компонентов (admin-панель, ORM). Flask проще, но уступает FastAPI в производительности и возможностях валидации.

**Язык программирования клиентской части: JavaScript (ES6+)**

JavaScript является стандартным языком программирования для веб-браузеров и обеспечивает создание интерактивных пользовательских интерфейсов.

**Фреймворк клиентской части: React 19**

React — библиотека для построения пользовательских интерфейсов, разработанная компанией Meta (Facebook). Преимущества: компонентный подход, виртуальный DOM, большая экосистема, широкое сообщество.

Альтернативы: Vue.js, Angular. Vue.js — достойная альтернатива, но React имеет более широкую экосистему компонентов. Angular избыточен для проекта данного масштаба.

**Библиотека компонентов: Shadcn/UI + Tailwind CSS**

Shadcn/UI — набор переиспользуемых компонентов, построенных на Radix UI primitives и стилизованных через Tailwind CSS. Tailwind CSS — утилитарный CSS-фреймворк, обеспечивающий быструю стилизацию.

**Библиотека визуализации: Recharts**

Recharts — библиотека построения графиков для React, использующая SVG. Выбрана за удобный API, хорошую документацию и поддержку адаптивных графиков.

**Система управления базами данных: MongoDB 7.0**

MongoDB — документоориентированная NoSQL СУБД. Выбрана по следующим причинам: гибкая схема документов идеально подходит для хранения игрового состояния с вложенными структурами (инвентарь, настройки меню, достижения); высокая производительность при операциях чтения/записи; простота горизонтального масштабирования.

Альтернативы: PostgreSQL, SQLite. PostgreSQL обеспечил бы строгую типизацию, но потребовал бы сложных миграций при изменении структуры данных. SQLite подходит для локальных приложений, но менее удобен для веб-сервисов.

Motor — асинхронный драйвер MongoDB для Python, совместимый с FastAPI.

### 2.1.1 Описание и обоснование архитектуры системы

Разрабатываемое приложение «Кофейня: Мастерская вкуса» построено на основе **клиент-серверной трёхуровневой архитектуры**, включающей:

1. **Уровень представления (клиент)** — React-приложение, выполняющееся в веб-браузере. Отвечает за отображение пользовательского интерфейса, обработку действий пользователя и отправку запросов к серверу.

2. **Уровень бизнес-логики (сервер)** — FastAPI-приложение на Python. Содержит всю игровую логику: расчёт симуляции дня, генерацию случайных событий, проверку достижений, управление ресурсами.

3. **Уровень данных (база данных)** — MongoDB. Хранит состояния игр, статистику, логи событий.

Выбор трёхуровневой архитектуры обоснован необходимостью разделения ответственности между компонентами. Вся игровая логика сосредоточена на сервере, что обеспечивает:
- целостность данных (клиент не может модифицировать состояние напрямую);
- возможность одновременного доступа нескольких пользователей;
- простоту обновления бизнес-логики без изменения клиентской части.

Взаимодействие клиента и сервера осуществляется через **REST API** по протоколу HTTPS. Клиент отправляет HTTP-запросы (GET, POST, DELETE) к серверу, который обрабатывает их, взаимодействует с базой данных и возвращает ответы в формате JSON.

## 2.3 Обеспечение безопасности и надёжности данных

В разрабатываемой системе обрабатываются следующие данные: игровое состояние (баланс, инвентарь, настройки), статистика по дням и лог событий. Персональные данные пользователей не собираются (используется только имя игрока).

**Реализованные механизмы безопасности:**

1. **Валидация входных данных.** Все входящие запросы валидируются через Pydantic-модели FastAPI. Например, запрос на закупку ингредиентов проверяет корректность идентификаторов и положительность количества.

2. **Проверка состояния игры.** Перед выполнением действий сервер проверяет статус игры (active/won/lost), что предотвращает модификацию завершённых игр.

3. **Защита от некорректных операций.** Система проверяет достаточность средств при покупках, наличие необходимых предпосылок для улучшений, допустимость цен.

4. **Исключение _id из ответов MongoDB.** Все запросы к базе данных используют проекцию `{"_id": 0}`, что предотвращает утечку внутренних идентификаторов.

5. **CORS-политика.** Сервер настроен с поддержкой Cross-Origin Resource Sharing для безопасного взаимодействия клиента и сервера.

6. **Использование переменных окружения.** Все конфиденциальные параметры (URL базы данных, имя БД) хранятся в файлах .env и не включаются в исходный код.

**Обеспечение целостности данных:**

1. Все операции с базой данных выполняются атомарно через операции MongoDB `update_one` с оператором `$set`.
2. При удалении игры каскадно удаляются все связанные записи (статистика, логи).
3. Автосохранение выполняется после каждого завершённого дня и при каждом действии.

**Обеспечение надёжности:**

1. Обработка ошибок через try-except с возвратом понятных сообщений пользователю.
2. HTTP-коды ответов: 200 (успех), 400 (некорректный запрос), 404 (не найдено).
3. Логирование серверных событий через модуль logging.
4. Корректное закрытие соединения с БД при завершении работы сервера.

function playTone(freq, duration, type = 'sine', volume = 0.3, delay = 0) {
  const ctx = getCtx();
  const osc = ctx.createOscillator();
  const gain = ctx.createGain();
  osc.type = type;
  osc.frequency.setValueAtTime(freq, ctx.currentTime + delay);
  gain.gain.linearRampToValueAtTime(volume, ctx.currentTime + delay + 0.02);
  gain.gain.exponentialRampToValueAtTime(0.001, ctx.currentTime + delay + duration);
  osc.connect(gain);
  gain.connect(getMaster());
  osc.start(ctx.currentTime + delay);
  osc.stop(ctx.currentTime + delay + duration);
}

## Руководство администратора

### 1. Требования к серверу
- Python 3.10+, Node.js 18+, MongoDB 6.0+
- 1 ГБ RAM, 500 МБ диск

### 2. Установка
```bash
# Бэкенд
cd backend && pip install -r requirements.txt
# Фронтенд
cd frontend && yarn install
```

### 3. Настройка окружения
Файл `backend/.env`:
```
MONGO_URL="mongodb://localhost:27017"
DB_NAME="coffeeshop_game"
CORS_ORIGINS="*"
```

### 4. Запуск
```bash
# Сервер
cd backend && uvicorn server:app --host 0.0.0.0 --port 8001
# Клиент
cd frontend && yarn start
```

### 5. Мониторинг
Логи сервера записываются через модуль logging. Для просмотра используйте стандартные средства ОС.

### 6. Резервное копирование
```bash
mongodump --db coffeeshop_game --out /backup/$(date +%Y%m%d)
```
